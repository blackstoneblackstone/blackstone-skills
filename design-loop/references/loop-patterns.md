# Loop 模式参考

仅在选择循环类型、比较方案或提供示例时读取。

## 快速决策树

1. 一次对话内可以完成吗？可以：回合制。
2. 完成状态可自动测量，并需要多次改进吗？可以：目标导向。
3. 需要等待外部状态改变吗？可以：事件驱动；没有事件源时才用定时轮询。
4. 是否持续接收多个任务，并需要分流、并发、升级和队列状态？是：主动式。

不要为了“更自主”直接选择主动式。复杂度按回合制 → 目标导向 → 事件/定时 → 主动式逐级增加。

循环类型描述“何时反复运行”，自主等级描述“无需人工可以走多远”，评估隔离等级描述“结果有多可信”。三者分别选择，不要混为一个标签。

## 模式对比

| 模式 | 典型触发 | 主要停止方式 | 必要护栏 | 示例 |
|---|---|---|---|---|
| 回合制 | 用户请求 | 当前任务完成或需要输入 | 清晰验收、执行后验证 | 实现一个按钮并跑测试 |
| 目标导向 | 用户启动目标 | 达标、轮数/预算耗尽、无进展 | 独立评估器、指标基线 | 性能分数提升至阈值 |
| 事件驱动 | webhook、队列消息 | 当前事件处理完毕 | 去重、幂等、死信队列 | 新 PR 出现后检查 CI |
| 定时轮询 | cron、云端计划 | 队列清空或人工取消 | 时区、锁、合理间隔 | 每日生成摘要草稿 |
| 主动式 | 事件与计划组合 | 单任务退出；服务持续 | 状态机、并发上限、审批、隔离 | 持续分诊缺陷队列 |

## 示例一：网页性能目标循环

- 目标：移动端实验环境的性能指标达到约定阈值。
- 触发：开发者手动启动。
- 周期：测量基线 → 定位最大瓶颈 → 做一个可逆改动 → 重测 → 保留或回滚。
- 成功：连续两次测量均达标。
- 停止：成功、5 轮、60 分钟、预算上限或连续 2 轮无改善。
- 风险：跑分波动；使用多次测量和固定环境降低噪声。
- 防刷分：锁定评估脚本、数据集、样本数和每轮墙钟预算；执行者只可修改约定实现文件。

## 示例二：PR 事件循环

- 触发：PR 新建、更新或评审意见事件。
- 去重：仓库 + PR 编号 + commit SHA + event ID。
- 周期：读取差异和检查 → 分类 → 仅处理授权范围内问题 → 跑测试 → 草拟或提交结果。
- 成功：目标 SHA 的必需检查通过，所有所选意见均处理或说明无法处理。
- 停止：等待审批、需要产品决策、两次相同失败或超时。
- 风险：旧事件覆盖新提交；行动前再次确认 HEAD SHA。

## 示例三：持续工单分诊

- 触发：新工单事件；低频计划负责遗漏补偿。
- 状态：new → classified → awaiting-approval → actioned → verified → closed/failed。
- 子任务：分类可使用轻量模型；复杂诊断升级到高性能模型；外部回复需审批。
- 成功：每个工单都进入终态或明确等待状态。
- 护栏：并发上限、租约锁、幂等回复键、死信队列、每日预算和积压告警。

## 常见反模式

- “一直尝试直到成功”：没有轮数、时间、预算和无进展上限。
- “每分钟检查一次”：未验证数据是否真的每分钟变化。
- “修复所有问题”：对象、优先级和完成状态都不明确。
- “执行成功就算完成”：没有读取结果或独立验证。
- “失败就重试”：具有付款、发布、回复等副作用时可能重复执行。
- “让多个 agent 投票”：没有独立证据时，多数意见不等于正确。
- “保存完整对话作为状态”：难以恢复和审计；应保存结构化 checkpoint。
- “规划者、生成者、评估者永远必须是三个 Agent”：低风险任务中可能徒增成本；按评估风险选择隔离等级。
- “失败就清空一切重启”：对不可安全重放的外部副作用会造成重复执行。
- “指标提高就是成功”：执行者可能改写评估、减少样本或牺牲关键约束指标。
